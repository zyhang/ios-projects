# AGENTS.md

## 产品概述

**Gleem** — 面向海外的隐私广告拦截：Safari + 系统级全 App 拦截，内置规则包，一次 IAP 解锁。

产品文档、线框图、高保真设计统一放在 [`docs/`](docs/)（见该目录 README）。

- **App 显示名**：Gleem  
- **副标题（已锁定）**：Block Ads & Trackers  
- 理想/立场文案放描述、截图与 About，不塞进副标题（见 `docs/product/naming.md`）

## 规则

### 1. 目标用户与产品定位（必须遵守）

本 App 面向**欧美等海外用户**设计与迭代。

后续所有工作——包括但不限于：

- 产品设计与信息架构
- 交互与视觉习惯
- 文案语言、语气与用词
- 功能取舍与优先级
- 默认行为与可选项设计

都必须贴合该客户群体的使用场景与预期，**不得偏离**（例如不得按中文市场习惯、国内浏览器生态或本地运营逻辑做默认假设）。

默认语言与文案基调为**英文**（美式/国际通用英文即可），面向重视隐私、愿意为工具付费的海外用户。

### 2. 隐私优先：本地处理，不采集浏览信息（必须遵守）

与 Wipr 同级的信任标准：**注重用户隐私**。

- **浏览相关信息留在本地**：用户访问了哪些站点/App、哪些请求被拦截等，默认不上传、不用于画像或分析。
- **App 不采集**个人数据与浏览行为（无广告 SDK、无第三方分析 SDK、无静默追踪）。
- 架构选型优先 Content Blocker、URL Filters 等**系统代为拦截、扩展不必读取页面内容**的路径；避免「为了统计/调试而拿到浏览数据」的设计。
- 若某能力**必然**需要更高权限或离开设备的查询（例如 URL Filters 的 PIR 查询），必须：
  - 走系统提供的隐私保护路径（如 PIR，使运营方无法得知用户查了什么）；
  - 在产品与隐私说明中写清「我们看不到什么」；
  - **不得**借机收集可还原浏览历史的日志。
- 可选反馈/报错：仅用户主动提交；可匿名；提交内容最小化；用完即删；不得与浏览历史绑定做后台采集。
- 功能取舍冲突时：**隐私与本地优先 > 功能炫技**（例如不做需要读浏览数据才能实现的拦截统计，除非将来有纯本地、零上传方案）。

## 产品决策（已对齐）

相对同类极简拦截器（如 Wipr）的定位：

| 维度 | 决策 |
|------|------|
| 路线 | 同人群略扩：补对方故意不做/另收费的能力，不做正面堆功能的「更重版」 |
| 主楔子 | **系统级全 App 拦截**更好/更划算（对齐 Filtr 能力，基于 Apple URL Filters） |
| 主赢法 | 系统级拦截**打进基础买断价**，不为该项另设核心 IAP |
| 副楔子 | **内置规则包**（结构 B）：Core 必开 + Annoyances / Strict 可选叠加；**不提供**用户自定义规则 |
| 定价叙事 | 「更便宜」只作辅助，**不当**第一购买理由；信任、完整性与维护优先 |
| 商业结构 | **免费下载 + 非消耗型 IAP 一次解锁全部能力** + **Family Sharing**；解锁含 Safari + 系统级 + 规则包 + 名单维护权益（不拆第二桩系统级 IAP） |
| 价格政策 | **略低于 Wipr 基础买断价**（建议 ≤$1 差距，上架前按现价校准）；系统级含在买断内；**不以大幅低价/「更便宜」作主卖点** |
| 名单策略 | **混合分层（C）**：社区优质源 + 精选策展，经自有编译/QA 下发；Core/Annoyances/Strict 源可不同；自有补丁与 exception；遵守许可证与致谢 |
| 破站自救 | **B**：全局暂停 + Safari 按站放行 + 状态页说明如何关系统级 Filter + 可选主动报错（最小化、可匿名） |
| 商店形态 | **免费下载 + 一次非消耗型 IAP 全解锁** + Family Sharing |
| 开工顺序 | **设计先行**：名称 → 线框 → 视觉；URL Filter 等技术 spike **并行/紧随**，不阻塞第一轮品牌与 UI，但上架前必须通过 |
| 命名方向 | **A 工具/短动作感** + **常规英文词的变体**（易读、减撞名）；避免 Wipr/Filtr 仿名与杀毒腔 |
| 隐私 | **本地优先、不采集浏览信息**；无广告商；无「可接受广告」 |
| MVP 能力 | **A**：Safari Content Blocker + 系统级 URL Filter + 少量内置规则包 + 基础 onboarding/诊断（day‑1 兑现主楔子） |
| MVP 平台 | **Universal**：iPhone + iPad + Mac 同步可用（团队有能力做到 Mac 体验完整） |
| MVP 后置 | Web Extension（Extra 级）、复杂报错后台、Live Help、拦截统计、Vision 等 |
| 系统级后端 | **先 spike 再锁**：默认冲自建 PIR + 预过滤管线；搞不定则 v1 缩小名单/降刷新频率，**不**砍系统级主楔子 |
| 不做 | 中文/区域深度当差异化；自由自定义过滤规则；以低价当品牌主轴；后台采集浏览数据 |

技术方向（事实约束）：

- Safari：Content Blocker +（如需要）Web Extension 做深层规则
- 全 App：iOS / iPadOS / macOS 26+ 的 **URL Filters**（非 VPN；可与 VPN / Private Relay 并存）
- 名单持续维护；无广告商关系；不为「可接受广告」开后门
- 任何遥测/分析默认关闭且优先不做；名单更新只拉取规则，不回传浏览行为
